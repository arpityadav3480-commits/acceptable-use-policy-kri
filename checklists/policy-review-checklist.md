# Annual Policy Review Checklist

**For:** the Information Security Lead (policy owner)
**Policy:** KRI-ISP-001 Acceptable Use Policy · Kestrelwood Research Institute (*fictional*)
**Scheduled review due:** 1 November 2027 (Section 14)

## 1. Triggers since the last review

| Question | Yes/No | Notes |
|---|---|---|
| Was there a significant security incident? | | |
| Did any relevant law or regulation change (for example the DPDP Act rules or CERT-In directions)? | | |
| Was major new technology adopted (cloud, AI or research platforms)? | | |
| Was there a significant organisational change (new teams, sites or partners)? | | |
| Were there audit findings or funder requirements affecting this policy? | | |

## 2. Content review

- [ ] The scope still covers all user types and all assets in use.
- [ ] The Approved Services List and AI tool rules are current.
- [ ] Password, MFA and device requirements still match current NIST and CIS guidance.
- [ ] The data classification examples reflect current research projects.
- [ ] Incident contacts (extension, email, on-call number) are correct.
- [ ] The monitoring notice matches the tools actually in use and the actual log retention periods.
- [ ] Breach levels and the escalation path match HR's disciplinary procedure.
- [ ] The exception process works in practice (check the timings in the Exception Register).
- [ ] References to standards and laws are up to date.

## 3. Evidence to look at

- [ ] Acknowledgement completion rate (target: 100% of active users)
- [ ] Number and types of incidents reported, and the time taken to report
- [ ] Number of breaches by level
- [ ] Active and expired exceptions in the Exception Register
- [ ] Feedback from users, PIs and HR
